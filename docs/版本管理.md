## 版本约定

- 汉化字节、安装行为或兼容性改变：发布新的补丁版本，例如 v0.2.5；同时更新 manifest、构建版本、README、使用说明和 CHANGELOG。
- 只有样图、说明或目录导航改变：提交文档更新，保持补丁版本不变。
- 影响范围明显扩大时增加次版本；尚未全面汉化和验证的版本继续标为预发布。

## 开发与发布流程

1. 开始工作前运行 `git fetch origin --tags` 和 `git status --short`，确认当前状态；新功能可创建 `codex/功能名称` 分支。
2. 修改后检查差异，运行适用的单元、差分和安装检查。构建顺序及公开打包边界见 [开发与发布](开发与发布.md)。
3. 按一个明确主题提交，标题说明具体变化。推送前检查远端更新，保留原有历史；不对 main 强制推送。
4. 新发布以已经核验的提交创建新的版本标签（示例仅在真正发布 v0.2.5 时执行）：

```powershell
$verifiedCommit = '替换为已核验的提交SHA'
git tag -a v0.2.5 -m "ChemDraw Chinese patch v0.2.5" $verifiedCommit
git push origin main
git push origin v0.2.5
```

5. 上传该标签对应的安装包、源码包和 SHA256.txt，核对远端大小及哈希后发布。不可将旧标签改指向新提交，或静默覆盖旧附件。

## 查看与恢复源码

```powershell
git log --oneline --decorate -10
git diff v0.2.3..v0.2.4
git switch -c codex/review-v024 v0.2.4
```

第三条命令创建检查分支，不重置 main。以上操作只管理项目源码；恢复软件英文界面仍使用“一键还原英文.cmd”。

打包工具不会覆盖内容不同的同名 ZIP。只有说明和样图更新时，可另存文档快照，不替换已有 Release 附件：

```powershell
python tools/package_release.py --output-dir dist/docs-snapshot-20261014
```

安装器与差分版本仍为 v0.2.4，该单独目录内的快照不等同于原 v0.2.4 发布附件。
